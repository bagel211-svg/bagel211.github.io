貫穿全課的核心概念

優化輸入，而非權重
ML 訓練是優化模型權重。攻擊則是固定權重，優化輸入——用完全相同的梯度下降工具，只是目標不同。這個視角統一了規避、反轉、萃取等看似不同的攻擊。
存取等級決定攻擊策略
Open Box 有梯度 → CW L2
Gray Box 有機率 → SimBA
Closed Box 只有標籤 → HopSkipJump

先確認你有什麼存取權，再選擇對應的攻擊。
No Free Lunch
沒有萬用的最佳演算法。每個模型、每個場景需要不同的超參數和策略。用 Optuna 這類 HPO 工具自動搜索，而不是手動猜測。
傳統安全知識仍然適用
ML 不應獲得「因為是 AI」的安全豁免。PII 洩漏、code execution、access control、input validation——這些傳統安全概念在 ML 系統中同樣重要，只是攻擊面的形式不同。
01

核心定義

Model Evasion 模型規避
產生一個刻意讓模型誤分類的樣本，同時保留某種對攻擊者有用的屬性（例如：對人類看起來仍然正常）。

核心思路：找到一個擾動（perturbation），讓輸入越過決策邊界（decision boundary），但不破壞輸入的「有用屬性」。
不針對特定類別（Untargeted）
只要讓模型誤分類就好，不在意最終被歸入哪個類別。例：讓狗的照片被分類成「不是狗」的任何東西。
針對特定類別（Targeted）
強迫模型將輸入分類到特定的目標類別。例：讓狗的照片被分類成「開瓶器（corkscrew）」。

Carlini & Wagner L2 攻擊原理

核心洞見
不優化模型權重，而是優化輸入圖片（mask）。利用和訓練模型相同的優化工具，只是改變目標。
同時優化兩個目標：
目標 1 — 誤分類
最大化正確標籤的 classification loss（Untargeted），或最小化目標標籤的 loss（Targeted）
目標 2 — 最小擾動
最小化 mask（擾動）的 L2 norm，讓圖片看起來盡量不變
Loss Function 設計
Untargeted（不針對特定類別）
total_loss = −cross_entropy(output, true_label) + L2_norm(mask)

加上負號 → 推離正確標籤 → 迫使模型誤分類
Targeted（針對特定類別）
total_loss = cross_entropy(output, target_label) + l2_weight × L2_norm(mask)

移除負號，改為最小化目標類別的 loss；加入 l2_weight 允許更大的擾動

核心程式碼解析

STEP 1 建立 Mask Parameter
+

# 建立隨機初始化的 mask（很小的噪音）
mask = torch.randn_like(img_tensor) * 1e-3

# 轉成 Parameter → 讓 optimizer 可以更新它
mask_parameter = torch.nn.Parameter(mask.to(device))

# 對 mask 設定 optimizer（不是對模型！）

💡 關鍵：我們優化的是 mask，不是模型權重。模型保持不變（eval mode）。

STEP 2 Untargeted Loss Function
+
Python · PyTorch
def loss_function(output, mask, current_index):
    # 負號！推離正確標籤
    classification_loss = -torch.nn.functional.cross_entropy(
        output, current_index
    )
    
    # L2 懲罰：不讓任何像素變太大
    l2_loss = torch.pow(mask, 2).sum()
    
    total_loss = classification_loss + l2_loss
    return total_loss, classification_loss, l2_loss
STEP 3 Targeted Loss Function
+
Python · PyTorch
# target_index = 513（corkscrew 開瓶器）
target_index = torch.tensor(
    labels.index('corkscrew')
).unsqueeze(0).to(device)

def loss(output, mask, target_index, l2_weight=0.5):
    # 沒有負號！直接最小化目標類別的 loss
    classification_loss = torch.nn.functional.cross_entropy(
        output, target_index
    )
    l2_loss = torch.pow(mask, 2).sum()
    
    # l2_weight=0.5 → 允許更大的擾動（L2 距離翻倍）
    total_loss = classification_loss + (l2_weight * l2_loss)
    return total_loss, classification_loss, l2_loss

⚠️ Targeted 比 Untargeted 更難，需要允許更大的擾動（降低 l2_weight）。

重要觀察與防禦思路

⚠️
有損格式的威脅（JPEG vs PNG）：將對抗樣本存為 JPEG（有損壓縮）後重新載入，通常會破壞攻擊效果，因為微小的像素擾動被壓縮掉了。PNG（無損）則通常保留攻擊效果。這代表現實中部署攻擊時需要額外工作。
🔍
隨機噪音觀察：即使是看起來像純噪音的圖片，模型仍然會以高信心預測某個類別。這是因為模型對訓練分佈之外的輸入沒有「拒絕回答」的機制。
📊
Targeted vs Untargeted 的差異：觀察兩種攻擊後原圖與對抗樣本之間的像素差值直方圖（差值的範圍和形狀）。Targeted 攻擊通常需要更大的擾動（更寬的分佈），因為必須讓模型收斂到特定類別。
🛡️
潛在防禦方向：既然存成檔案再讀取有時可以破壞攻擊，其他輸入轉換（如：影像壓縮、隨機縮放、加入少量噪音）也可能作為防禦手段（Input Transformation Defenses）。
⚡ l2_weight 參數的意義
在 Targeted 攻擊中，l2_weight = 0.5 代表允許擾動的大小是原本的 2 倍，因為對 L2 懲罰乘以 0.5 等於減少它的影響力。這讓優化過程有更多空間找到目標類別，代價是圖片視覺上可能稍微失真。

SimBA — 灰盒梯度估計攻擊

SimBA（Simple BlackBox Attack）核心思路
無法存取梯度時，使用大量隨機 mask 來「猜」梯度方向：對每個隨機 mask 測試它是否讓目標類別分數下降（或讓目標類別分數上升），只保留有效的步驟——類似「冷熱遊戲」。
演算法邏輯（Algorithm 1 from SimBA paper）
1
預先生成隨機 mask 集合
產生 n_masks = 1000 個隨機 tensor，每個都乘以很小的 eta = 0.005（步長）
2
隨機抽取候選 mask
每次從集合中隨機抽一個 mask，套用到當前圖片：img + current_mask + mask_candidate
3
比較分數
Untargeted：若原始標籤分數下降 → 接受此步驟
Targeted：若目標標籤分數上升 → 接受此步驟
4
累積有效的 mask
current_mask += mask_candidate，重複直到誤分類成功
💡
為什麼這算「梯度估計」：隨機 mask 採樣並觀察 loss 的變化，本質上是在估計 loss 對各個方向的敏感度——這正是梯度在做的事。只是比直接計算梯度嘈雜很多，需要更多 query。

SimBA 程式碼解析

Untargeted 不針對特定類別攻擊
+

current_mask = torch.zeros_like(img_tensor).to(device)
starting_label = model(img_tensor).argmax(1)
current_label = starting_label

# 記錄原始標籤的「最佳分數」（我們要讓它下降）
best_score = model(img_tensor + current_mask)[0, starting_index.item()].item()

while current_label == starting_label:
    # 隨機抽一個候選 mask
    mask_candidate = mask_collection[np.random.choice(len(mask_collection))]
    
    with torch.no_grad():
        output = model(img_tensor + current_mask + mask_candidate)
    
    current_label = output.argmax(1).item()
    new_score = output[0, starting_label.item()].item()
    
    # 若原始類別分數沒下降 → 放棄這個 candidate
    if new_score >= best_score:
        continue
    
    # 分數下降 → 接受，更新 mask
    best_score = new_score
    current_mask += mask_candidate

⚠️ 注意：不使用 optimizer，完全靠「接受/拒絕」機制逐步累積擾動。

HopSkipJump — 閉合盒攻擊（只有標籤）

攻擊情境
API 只回傳預測的類別名稱，沒有任何機率或分數。這是最困難的攻擊場景。HSJ 不使用梯度（即使實驗時可以存取模型，HSJ 演算法本身也不依賴它）。
四步驟核心流程
1
Hop — 找到初始誤分類錨點
對原始圖片加入大量隨機噪音，直到找到一張讓模型誤分類的圖片，作為「另一側的錨點（anchor）」。
2
Skip — 二分搜尋逼近決策邊界
在原始圖片與錨點之間做二分搜尋（bisection search），找到最接近決策邊界的點——讓誤分類的圖片盡可能靠近原始圖片。
3
Jump — 估計梯度並跳躍
在決策邊界附近採樣大量隨機擾動，計算哪些保持誤分類 vs 哪些不保持，以此估計梯度方向，然後朝該方向跳躍到新的錨點。
4
重複 2→3 直到收斂
每次迭代後，誤分類的圖片應該愈來愈接近原始圖片（L2 距離縮小），最終在視覺上難以區分。

HopSkipJump 程式碼解析

STEP 1 找初始誤分類圖片
+
Python · HopSkipJump
def adversarial_satisfactory(samples, target, clip_min, clip_max):
    samples = torch.clamp(samples, clip_min, clip_max)
    with torch.no_grad():
        preds = model(samples).argmax(dim=1)
    return preds != target  # 只要不是原始類別就算成功

# 嘗試 10 次找到一張誤分類的隨機圖
for _ in range(10):
    random_img = torch.FloatTensor(img_tensor.shape).uniform_(clip_min, clip_max)
    if adversarial_satisfactory(random_img, y_original, clip_min, clip_max):
        initial_sample = (random_img, y_original)
        break
STEP 2 二分搜尋逼近決策邊界
+
Python · Bisection Search
# threshold：決定要逼近到多近
threshold = 0.01 / torch.sqrt(torch.prod(torch.tensor(img_tensor.shape, dtype=torch.float)))

upper_bound, lower_bound = 1, 0

while (upper_bound - lower_bound) > threshold:
    midpoint = (upper_bound + lower_bound) / 2.0
    
    # 線性內插：在原圖 ↔ 隨機圖之間取中間點
    interpolated = (1 - midpoint) * img_tensor + midpoint * random_img
    
    if adversarial_satisfactory(interpolated, y_original, clip_min, clip_max):
        upper_bound, lower_bound = midpoint, lower_bound  # 邊界在前半段
    else:
        upper_bound, lower_bound = upper_bound, midpoint  # 邊界在後半段

boundary_adversarial_example = (1-upper_bound)*img_tensor + upper_bound*random_img

想像兩張圖在同一條街上，邊界在它們之間某處——二分搜尋就是在找那個門牌號碼。

STEP 3 隨機採樣估計梯度方向
+
Python · Gradient Estimation
# 在邊界附近採樣 500 個隨機擾動
gradient_samples = 500
perturbations = torch.randn(*perturbation_shape).to(device)

# 正規化每個擾動（確保大小一致）
perturbations = perturbations / torch.sqrt(torch.sum(
    perturbations**2, axis=tuple(range(len(perturbation_shape)))[1:], keepdims=True
))

eval_samples = torch.clamp(boundary_adversarial_example + perturbation_scale*perturbations, clip_min, clip_max)
eval_labels = adversarial_satisfactory(eval_samples, y_original, clip_min, clip_max)

# +1 = 仍然誤分類（成功），-1 = 回到原始類別（失敗）
signs = torch.where(eval_labels, 1., -1.).reshape([gradient_samples, 1, 1, 1])

# 梯度估計 = 誤分類樣本的均值 - 未誤分類樣本的均值
mean_signs = torch.mean(signs)
unnormalized_gradient = torch.mean((signs - mean_signs) * perturbations, axis=0)
normalized_gradient = unnormalized_gradient / torch.norm(unnormalized_gradient)
🧭
Pop Quiz 解答：normalized_gradient 與 img_tensor 形狀相同，因為它表示「每個像素應該往哪個方向移動」的指引——梯度就是圖片空間中的一個方向向量。
STEP 4 跳躍到新錨點
+

done = False

比較項目 CW L2（Open Box） SimBA（Gray Box） HopSkipJump（Closed Box）
梯度取得方式 直接計算（backward） 從分數估計（random mask 接受/拒絕） 從標籤估計（邊界採樣）
所需 API query 數 最少 中等 最多
圖片品質（L2 距離） 最小擾動 中等 擾動較大（可見失真）
像素差異分布 緊密集中 稍寬 分布最寬，變動範圍大
可偵測性（防守方角度） 難偵測（微小） 中等 Query 次數多，可透過流量分析偵測
⚠️
HSJ 的概率悖論：雖然 HSJ 的圖片品質較差（L2 距離大），但模型的預測信心卻可能更高——因為它是在找「剛好越過邊界」的點，而 CW 是讓 loss 最大化。
🛡️
防守方啟示：無論使用哪種攻擊，都會在查詢模式中留下「訊號」（signal in noise）。大量異常 query、特定 pixel 分布的輸入，都可以作為偵測指標。
🎯
優化思維（核心帶走）：一旦你把問題框架成優化問題，攻擊方法就只是「用什麼技術來驅動你想要的結果」。數據模態不同、存取等級不同，但優化的本質是一樣的。這個思維可以直接套用到繞過惡意軟體分類器、垃圾郵件過濾器等真實場景。
E-01

模型萃取攻擊定義

Model Extraction 模型萃取
透過對目標模型不斷發送查詢並收集輸出，訓練出一個功能等價（functionally equivalent）的複製模型。可用於洩漏智慧財產，或取得本地副本以供進一步的離線攻擊（例如生成對抗樣本再轉移）。
主要用途
1. 洩漏智慧財產（模型本身就是資產）
2. 取得本地副本 → 用 CW L2 等 open-box 攻擊生成對抗樣本 → 轉移到線上目標
為什麼「友善」？
萃取攻擊只需要標記一個資料集，不需要梯度，甚至不需要與目標模型相關的資料——只需要能送出 input 並收到 output。
E-02

成功萃取的三個前提

1
能送出 input 並觀察 output
需要某種形式的 API 存取。現實中的難點：不是每個 API 都支援 batch、輸入格式可能是 bytes 而非 tensor、輸出可能只有 top-5 標籤而非完整 logits。
⚠️ Opsec：發送 5000 張 224×224 圖片的流量模式在 log 中非常顯眼。
2
具代表性的資料集
你萃取的不是目標模型本身，而是在建模一個模型。如果你的資料集只覆蓋 50% 的訓練分佈，複製模型的準確度會更差。挑選接近目標領域的資料——如果是釣魚郵件模型，找郵件資料集而不是小說。
💡 進階：生成式技術（Generative AI）可以創造幾乎任何你需要的資料集。
3
合適的複製模型架構
不需要最新最強的架構。No Free Lunch 定理：沒有任何一個演算法在所有問題上都是最優的——最有效的演算法取決於問題的具體特性。多實驗，找到適合你任務的架構。
E-03

萃取攻擊完整流程

五步驟攻擊鏈
1
收集代理資料集
找一個與目標模型領域接近的公開資料集（本例使用 Caltech 101 圖片分類資料集）。
Caltech 101ImageNet subset或自行生成
2
用目標模型標記資料集
對代理資料集中的每張圖片，送到目標模型取得預測標籤（用 ExtractionDataset 自動化）。這就是你的訓練資料。
3
訓練複製模型（Copy-Cat）
用你標記好的資料集，微調（fine-tune）一個不同的預訓練模型（本例用 EfficientNet-B0，假裝不知道目標是 MobileNetV2）。
4
對複製模型生成對抗樣本
因為你有本地複製模型，可以直接使用 CW L2（open-box）攻擊，生成對抗樣本（此處將恐龍誤分類為飛機）。
5
嘗試轉移到目標模型
將本地生成的對抗樣本送到線上目標模型，檢查是否同樣被誤分類（transferability）。
⚠️
轉移失敗時的選項：收集更多目標模型的標籤資料 / 繼續訓練複製模型提高準確率 / 換用不同的複製模型架構 / 以上皆是。關鍵是：你在發送良性流量，在本地建模，然後周期性地取得反饋。

class ExtractionDataset(Dataset):
    def __init__(self, target_model, data_dir, transform=None):
        self.target_model = target_model
        self.image_filenames = glob.glob(data_dir + "**/*.jpg")
        self.transform = transform

    def __getitem__(self, idx):
        image = Image.open(self.image_filenames[idx]).convert('RGB')
        img_tensor = self.transform(image).unsqueeze(0)

            # 用目標模型自動取得標籤
            output = self.target_model(img_tensor.to(device)).argmax(1)

dataset = ExtractionDataset(target_model, "../data/101_ObjectCategories/", preprocess)

重要觀察與攻擊思路

準確率 ≠ 攻擊成功
複製模型的準確率可能不高，但只要它與目標模型在共同的輸入上有相似的判斷方式，對抗樣本就有機會轉移過去。標籤相同但機率分數差異很大是正常的。
Fine-tuning 的另一面
現代 ML 的主流訓練方式是取一個 base model 再 fine-tune。萃取攻擊就是這個流程的「攻擊版本」——你在用目標模型的 output 作為標籤來 fine-tune 你自己的模型。
🔍
模型的標籤映射是攻擊面：目標模型只知道 index → output，它本身不知道哪個 index 對應什麼標籤。如果你在 labels 陣列中換掉某個標籤的位置，模型輸出的文字描述就會錯——這本身也是一個攻擊面。
⚠️
前處理步驟本身也是攻擊面：模型需要特定的 input shape、正規化參數、批次格式。如果攻擊者能操控這些前處理步驟，就可以影響模型的輸出——無需修改模型本身。
🎯
策略性採樣 vs 隨機採樣：本例使用隨機採樣的代理資料集，效果不是最優。更進階的做法是策略性地選擇哪些 input 能最有效地揭示模型的決策邊界——例如優先選取邊界附近的樣本。

E-06

CVE-2019-20634 — Proof-Pudding 攻擊

攻擊背景
研究人員發現某郵件安全服務的郵件標頭（mail headers）會洩漏模型分數。他們利用退信機制（bounce）來收集分數：發送郵件到不存在的地址 → 郵件伺服器退信但已完成評分 → 標頭中包含評分資訊。
攻擊技巧細節
1
繞過發信方被標記為垃圾郵件
大量退信會讓發信服務商把你封鎖。解法：手動設定 return-path header 指向一個獨立的接收地址，讓發信方看不到退信率。
2
選用 Enron 資料集作為查詢語料
選擇與目標任務（電子郵件分類）高度相關的資料集。可以用隨機文字嗎？可以，但領域相關的資料能給你更有用的模型行為洞察。
3
收集標頭中的評分並建立資料集
從退信標頭中提取 mlxscore、mlxlogscore 等評分，配合郵件內容形成（input, score）的訓練對。
💡
mlxlogscore vs mlxscore：對數（log）函數可以反轉指數關係，讓乘法/除法變成加減法，方便數學分析。當你在標頭中看到帶有 log 後綴的分數，通常是對原始分數取對數——分布形狀會從長尾變成較均勻的鐘形。

探索性資料分析（EDA）技術

PCA（主成分分析）
將高維資料壓縮到 2D 用於視覺化。保留最大變異量：第一主成分沿資料最大展開方向，第二主成分沿次大方向。有損壓縮，但保留最多「本質」。
t-SNE
用條件機率建模高維 vs 低維的鄰近關係。高維中靠近的點在 2D 中也會靠近。關鍵超參數：perplexity（影響聚類行為）。無監督，但可以用標籤著色。
如何解讀這些圖
每個圓點 = 一封郵件，顏色深淺 = 評分高低。如果你看到顏色在空間中有明顯的聚集或漸層，代表模型有學到有意義的特徵。如果顏色隨機分布，代表你的特徵可能對模型沒有區分力。

這些圖都是無單位的——軸的數值沒有直接意義，重要的是相對位置和顏色分布。
E-08

傳統 NLP：TF-IDF 與 N-gram

TF-IDF 向量化
TF（詞頻）：一個詞在文件中出現多少次
IDF（逆文件頻率）：懲罰出現在太多文件中的詞（如 "the"、"is"）

結果：只有在當前文件中頻繁出現、但在其他文件中少見的詞，才會有高分——這些詞才有區分力。
N-gram
Unigram：單詞 ("download")
Bigram：雙詞 ("don't download")
Trigram：三詞序列

N-gram 越長，能捕捉更多語意，但特徵空間爆炸性增長。實務中通常用 (1,2) bigram 就夠了。
Word-Document Matrix（詞文矩陣）
TF-IDF 的輸出是一個稀疏矩陣（sparse matrix）：每列 = 一封郵件，每欄 = 一個 n-gram，值 = TF-IDF 分數。「稀疏」意思是大部分值都是 0（一封郵件不會包含所有可能的詞彙）。
CODE TF-IDF 向量化 + 相關性分析
+
Python · scikit-learn
# TF-IDF：移除英文停用詞，只保留出現 >0.1% 的詞，使用 bigram
vectorizer = TfidfVectorizer(stop_words="english", min_df=0.001, ngram_range=(1, 2))
vec = vectorizer.fit(df["content"])

# 建立詞-文矩陣 DataFrame，加上目標分數

corrs = df1[features].corrwith(df1["mlxlogscore"]).sort_values()

# Top 5 最「垃圾郵件相關」和最「正常郵件相關」的 n-gram
for i in range(5):
    print(f"Spammy: {corrs.index[i]}  |  Hammy: {corrs.index[-(i+1)]}")
🔑
這個相關性分析可以直接告訴你：哪些詞彙需要避免（高正相關 = 容易被判垃圾），哪些詞彙可以加入來降低分數——不需要訓練任何模型，純粹是統計分析。這就是「手動規避」的基礎。

HuggingFace AutoClass — 快速訓練 BERT

Tokenizer 概念
input_ids：文字轉換成數字 ID 的序列（每個詞/子詞對應模型詞彙表中的一個 ID）
attention_mask：1 = 真實 token，0 = padding（填充）。Transformer 的自注意力機制用這個來忽略填充部分，確保長短不一的文字可以組成正方矩陣做矩陣乘法。
標籤二值化：推斷決策邊界
模型輸出是 0–999 的分數，但分類模型通常需要 0 or 1。利用前面 EDA 發現的分數分布，設定一個閾值（threshold）：分數 ≥ threshold → 1（垃圾），否則 → 0（正常）。
⚠️
類別不平衡陷阱：如果你的資料集中 99% 都是 0，模型可能學會「永遠預測 0」來獲得 99% 準確率——但這個模型完全沒用。永遠搭配混淆矩陣（Confusion Matrix）來評估，不要只看 accuracy。
CODE HuggingFace AutoClass 完整流程
+
Python · HuggingFace Transformers

    'input_ids': input_ids.tolist(),
    'attention_masks': attention_masks.tolist(),
    'labels': labels.tolist()
})

# 5. AutoClass 載入模型（num_labels=2 → 二元分類）
model = AutoModelForSequenceClassification.from_pretrained(
    "bert-base-uncased", num_labels=2).to(device)

# 6. Trainer API 訓練（大量超參數都有合理預設值）
trainer = Trainer(model=model, args=training_args,

trainer.train()

萃取 AMSI（Windows Defender）

AMSI — Antimalware Scan Interface
Windows 的反惡意軟體掃描介面。PowerShell、JScript、VBScript、.NET 執行時會呼叫 amsi.dll，透過 RPC 將內容傳給安全產品（如 Windows Defender）掃描。

Defender 目前回傳 0（無害） 或 32768（惡意軟體），但規格允許 0–32767 之間的連續分數。≥32768 = AmsiResultIsMalware → 停止執行。
資料集來源
Lee Holmes & Daniel Bohanan 的 Blackhat 2017 演講「Revoke-Obfuscation」公開的 PowerShell 語料庫（含惡意與良性腳本）。用微軟提供的 AmsiStream.exe 對每個腳本取得 Defender 的標籤。
為什麼 AMSI 是好目標
AMSI 不是安全邊界（Microsoft 官方聲明）。現有的公開「繞過」大多靠 memory patching（amsi.dll 載入到同一個 process space，沒有 privilege 邊界）。ML 萃取則提供了另一個角度。

萃取攻擊策略思考

輸出格式的影響：連續值 vs 二值
輸出類型資訊量攻擊難度例子
連續值 0~1 每次微小改動都有反映 最容易 mlxlogscore、softmax 機率
Top-K 標籤 中等 中等 API 回傳 top-5 類別
二值 0/1 大幅改動才有反應 最困難 AMSI（0 或 32768）
📊
多樣性優先：採樣策略可以是：從一個起始樣本開始，每次選距離最遠的下一個樣本——確保你不會一直在相似樣本上浪費 query 配額，而是盡量探索整個輸入空間。
⚠️
Idempotent 程式碼：資料轉換要寫成「冪等」的——無論執行幾次結果都相同。例如用條件式 drop 而不是寫死欄名，避免重複執行出錯。
🎯
萃取攻擊的本質：你同時是 Data Scientist + ML Engineer + Red Teamer。光是把資料丟給模型可以成功，但更周全的做法是——把資料集和模型的工程設計，當成縮小搜索空間、逼近目標結果的手段。想知道模型對 X 的看法？送它各種 X。版本控管你的資料集，記錄 metadata。
I-01

模型反轉攻擊定義

Model Inversion 模型反轉
透過反向「查詢」模型，重建出近似訓練資料的樣本。把模型想像成一個有損壓縮演算法——它保留了訓練資料的部分信息，但如何提取出來才是難點。

⚠️ 注意：你得到的是訓練資料的近似表示，不是 1:1 的原始資料副本。攻擊需要大量 query，且在現實模型上往往不精確。
適合的目標
當模型對某個類別過擬合（overfit）時效果最好——模型有效地記住了那個類別。臉部辨識是典型案例：同一個人的照片高度相似，模型對其有強烈反應。
不適合的目標
MobileNet（1000 類）：每個類別的訓練樣本多樣性極高，模型不會「記住」特定樣本，反轉結果非常嘈雜，幾乎無法辨識。
I-02

MIFace 攻擊原理

核心思路——和生成對抗樣本幾乎一樣
與其優化「mask」讓模型誤分類，這次我們優化「輸入圖片本身」，讓它最大化某個目標類別的輸出分數——如果模型對某個輸入反應強烈，代表它可能在訓練資料中見過類似的東西。
攻擊步驟
1
初始化為「平均圖片」
從所有像素值均為 0.5 的圖片開始（灰色）——這是最中性的起點，不偏向任何特徵。
2
梯度下降優化輸入（不是權重）
最小化目標類別的 cross-entropy loss → 讓模型越來越確信這張圖是目標類別。使用 torch.clamp 確保像素值在合法範圍 [0,1] 內。
3
（可選）加入領域知識懲罰項
若已知背景應為黑色（如 MNIST），在 loss 中加入 + x.abs().sum() * price——懲罰非零像素，讓優化器只在「值得」的地方設置亮點，減少噪音。
⚠️
Price 參數的 tradeoff：太大 → 優化器放棄，回傳全黑圖片；太小 → 圖片極度嘈雜。需要針對每個模型和類別手動調校，或用 Optuna 自動搜索。

從 Diffusion Model 萃取訓練資料

研究基礎：Carlini et al. 2023

攻擊方法論（Section 4.2.1）
1
用大量 seed 生成圖片
對同一個 prompt，用 500 個不同的隨機種子各生成一張圖。
2
找出「相似群組（clique）」
計算所有圖片對之間的 MSE 或 L2 距離——如果多張圖片彼此非常相似（低 MSE），它們很可能都在收斂到同一個訓練樣本。
3
顯示或排序高相似度的圖片
過濾 MSE 低於閾值的圖片，或按照圖片間的「重複程度」排序——出現次數最多的最可能是訓練樣本。

P-01

資料投毒（Data Poisoning）

Data Poisoning 資料投毒
在訓練資料中植入惡意樣本，使訓練後的模型在看到特定觸發詞（trigger）時，執行攻擊者預定的行為——即「後門（backdoor）」。正常輸入下行為不變，只有觸發詞出現時才啟動。

如同擁有主機的物理存取權——你想做什麼取決於你的目標。
攻擊場景
· 特定輸入 → 預定輸出（後門）
· 規避可解釋性演算法
· 蓄意破壞模型效能
· 強迫模型輸出攻擊者想要的任何內容
· 極端案例：自駕車把「行人」→「綠燈」（致命）
為什麼危險
· 資料集透過集中倉庫共用 → 一次投毒影響多個模型
· 沒有回滾流程很難恢復
· 若組織沒有 DFIR 程序，可能永遠不知道被投毒了
⚠️
實際操作警告：若沒有完善的回滾程序，不建議對生產系統執行投毒攻擊。可能跨越多個下游系統，且難以復原。先理解機制，再在隔離環境測試。

Foundation Model
訓練目標：預測最有可能的下一個 token。不擅長指令遵循或對話。GPT-2 原版是此類。

Instruction-Tuned

訓練產生自然對話的多輪互動。如 ChatGPT、Claude。通常有系統提示（system prompt）框定行為邊界。

LoRA Fine-tuning 原理

LoRA — Low-Rank Adaptation
完整 fine-tune 大型 LLM 需要更新所有參數，代價極高。LoRA 的思路：在原始權重矩陣旁邊插入一個低秩矩陣（low-rank matrix），只訓練這個小矩陣的參數——訓練參數量可以降低 100 倍以上。
LoRA 關鍵超參數
參數意義本例值
r低秩矩陣的秩（rank）——越大，可訓練參數越多，但記憶體消耗增加8
lora_alpha縮放因子，控制 LoRA 層對原始權重的影響程度32
target_modules要插入 LoRA 的層名稱（不同架構不同）c_attn, c_proj, c_fc
lora_dropout防止過擬合的 dropout 比率0.05

L-12

從 LLM 萃取訓練資料（Carlini et al.）

核心假設
模型對它完全記憶的文字應該有更高的信心——當模型見到它曾在訓練中見過的完整句子時，預測每個下一個 token 的「驚訝程度」（perplexity）應該更低。

利用這個特性：大量生成文字 → 用模型檢查自己的輸出 → 過濾出「低困惑度」的候選 → 很可能是訓練資料。
Perplexity vs NLL（負對數似然）
NLL（Negative Log-Likelihood）：模型的訓練 loss，越低代表模型認為該序列越「正常」
Perplexity = exp(NLL)——對 NLL 取指數。兩者排序完全相同：低 NLL = 低 Perplexity = 更可能被記憶

實作上直接用 NLL 即可，省略 exp 步驟不影響排序結果。

L-14

四種評分方式比較

評分方式原理過濾目標實作
NLL / Perplexity 模型訓練 loss；越低代表越「熟悉」 基礎篩選 model(ids, labels=ids).loss
zlib 比對 NLL / zlib壓縮大小。若文字本身就很容易壓縮（重複性高），那低 NLL 不代表「記憶」而只是「無聊」 過濾 "AAAA..."、"1234..." 類型 nll / log2(len(zlib.compress(text)))
小寫比對 若模型精確記憶了特定大小寫格式，小寫版本對模型而言應該更「陌生」（更高 NLL） 確認是特定格式被記憶，而非通用語言模式 nll / nll_lowercase
滑動視窗 Perplexity 對文字的每 50 個連續 token 子集計算 perplexity，取最小值——即使全文不是訓練資料，也可能有片段被記憶 偵測部分記憶 留作練習

def score_outputs(outputs, model=model):
    input_ids = outputs.clone()
    target_ids = input_ids.clone()
    
    # 把輸出當作 labels 送回模型 → 計算模型對自己輸出的 loss
    # loss 越低 = 模型越「確信」這段文字 = 越可能已記憶
    loss = model(input_ids, labels=target_ids).loss.detach().item()
    
    # detach() + del：防止 GPU VRAM 洩漏
    del input_ids, target_ids
    return loss

# 使用範例
score = score_outputs(tokenizer("<|endoftext|>The quick brown fox",
    return_tensors='pt').to(device).input_ids)
⚠️

def gen(model, text=tokenizer.special_tokens_map['bos_token'],
        use_temperature_scaling=False):
    
    if use_temperature_scaling:
        # temperature 從 10 線性降到 1，每步生成 1 個 token
        temperature_scale = np.linspace(10, 1, 20)
        for t in temperature_scale:
            outputs = model.generate(**inputs, do_sample=True,
                max_new_tokens=1, top_k=40, temperature=t,
                pad_token_id=50256)
            text = tokenizer.decode(outputs.sequences[0], skip_special_tokens=True)
            inputs = tokenizer(text, return_tensors="pt").to(device)
        # 最後 236 個 token 用正常 temperature=1 生成
        outputs = model.generate(**inputs, do_sample=True,
            max_new_tokens=256-len(temperature_scale),
            top_k=40, temperature=1)
    else:
        # 標準固定 temperature 生成
        outputs = model.generate(**inputs, do_sample=True,
            max_new_tokens=256, top_k=40, temperature=1)
    
    scores = score_outputs(outputs.sequences[0], model=model)
    return outputs.sequences[0].detach().cpu(), scores

def compare_zlib(tokens):
    base_score = score_outputs(tokens.to(device))
    # 壓縮率 = zlib 壓縮後的 byte 數
    zlib_score = len(zlib.compress(
        tokenizer.decode(tokens, skip_special_tokens=True).encode('utf-8')))
    # 低 base_score（低 NLL）且高 zlib_score（高複雜度）= 真正被記憶的有意義文字
    return base_score / np.log2(zlib_score)

def compare_lowercased(tokens):
    test_string = tokenizer.decode(tokens, skip_special_tokens=True)
    inputs_lower = tokenizer(test_string.lower(), return_tensors="pt").to(device).input_ids
    score = score_outputs(tokens.to(device))
    score_lower = score_outputs(inputs_lower)
    del inputs_lower
    # score/score_lower < 1 = 小寫版本 NLL 更高 = 原始版本更可能是精確被記憶的格式
    return score / score_lower

TextAttack — 文字領域對抗攻擊

為什麼文字攻擊和圖像攻擊不同
圖像是連續函數——微小像素改變通常帶來微小輸出改變。文字是離散的——「fire」→「earth」在輸入空間很近（只換一個詞），但語義完全不同。擾動大小很難量化。
TextAttack 攻擊的四個組成元件
1 Goal Function
判斷攻擊是否成功。例：Untargeted 分類——只要把預測類別改掉就算成功。
2 Search Method
探索可能的文字轉換空間，尋找有效擾動。例：greedy search、beam search。
3 Transformation
實際對文字做什麼改動——同義詞替換、字元替換、改拼字（horrible→hrorible）。
4 Constraints
哪些轉換是有效的？編輯距離限制、語法檢查、語意保留——確保改完後對人類看起來還是合理的。

Alibi — 可解釋性作為安全工具

為什麼可解釋性與安全相關
Alibi 的演算法可以告訴你「模型在看什麼」——哪些像素/哪些詞對預測最重要。這不只是為了解釋，也可以用來指導攻擊：如果你知道模型依賴某個區域做判斷，你就知道該針對哪裡做擾動。
AnchorImage（圖像）
把圖片分割成 superpixel（超像素小塊），逐一遮蔽各塊，觀察哪些塊被移除時預測大幅改變。那些「anchor」超像素就是模型最依賴的視覺區域。

參數：threshold=.99（只顯示最關鍵的）、n_segments=30（分割成幾塊）
AnchorText（文字）
逐一遮蔽（mask）文字中的詞，觀察哪些詞被移除時預測改變。輸出 anchor 詞列表——這些詞是模型預測的關鍵錨點。

可用於：找出哪些詞可以安全替換（不影響分類）vs 哪些詞是關鍵。

A-08

Optuna — 超參數優化（HPO）

為什麼需要 HPO
每個攻擊演算法都有預設超參數，但這些預設值不一定是針對你的目標模型最優的。手動搜索是徒勞的。Optuna 用貝葉斯優化自動找到最好的超參數組合——它是「優化流程的優化器」，而不是優化資料。
貝葉斯優化流程（TPE 演算法）
1
定義先驗（Prior）
對超參數空間的初始假設——先隨機採樣幾個點，獲得基準觀測值。
2
更新後驗（Posterior）
TPE 建立兩個模型：l(x)（使結果變好的參數分布）和 g(x)（使結果變差的參數分布）。
3
選下一個採樣點（Acquisition Function）
計算期望改進（Expected Improvement）：EI ∝ l(x) / g(x)——優先探索「好參數可能性高、壞參數可能性低」的區域。平衡探索（exploration）與利用（exploitation）。
4
迭代
重複步驟 2–3，隨著 trial 數增加，估計越來越精準。不需要目標函數可微分——因此適合優化「黑盒流程」。

Python · Multi-objective Optuna
# ModelWrapper 加入 query 計數器
class ModelWrapper:
    def __init__(self):
        self.__reset__()

    def predict(self, x):
        with torch.no_grad():
            output = target_model(torch.from_numpy(x).to(device))
        probs = torch.softmax(output, dim=1).cpu().numpy()
        self.num_queries += 1   # 每次 predict 計數
        return probs

    def __reset__(self):
        self.num_queries = 0

def objective(trial, attack, x):
    model_wrapper.__reset__()   # 每次 trial 前重置計數
    attack.set_params(**{
        "max_iter": trial.suggest_int('max_iter', 10, 3000),
        "epsilon":  trial.suggest_float('epsilon', 1e-6, 1.0),
        "freq_dim": trial.suggest_int('freq_dim', 1, 20),
        "stride": 1, "batch_size": 1, "verbose": False
    })

    with torch.no_grad():
        results = attack.generate(x=x)

    l2_norm = torch.norm(img_tensor - results, p=2)
    num_queries = model_wrapper.num_queries

    return l2_norm, num_queries  # 回傳兩個值

# directions 對應兩個回傳值各自的優化方向
study = optuna.create_study(directions=["minimize", "minimize"])
study.optimize(
    lambda trial: objective(trial, attack=attack, x=img_tensor.numpy()),
    n_trials=100, show_progress_bar=True
)
📊
多目標優化的結果是一個 Pareto 前沿——一組「無法在不犧牲其中一個目標的情況下同時改善所有目標」的解。你可以根據實際場景的 tradeoff 從中挑選合適的點。

SimBA 超參數 × Optuna 搜索空間

超參數預設值 / 範圍意義對攻擊的影響
max_iter 10 – 3000 最大迭代次數 越大 → 攻擊更強但 query 更多；受 query budget 限制
epsilon 1e-6 – 1.0 每步擾動步長 越大 → 收斂快但圖片失真大；越小 → 擾動微小但需更多步
freq_dim 1 – 20 DCT 頻率維度 影響擾動在頻率域的搜索範圍；模型依賴的頻率不同
batch_size 固定 1 每次送幾個樣本 不是所有 API 支援 batch；設為 1 是最通用的選擇
⚠️
ART 的 batch_size 陷阱：如果你之前在 ART 的 predict 函數中看到輸入突然從 1 個樣本變成 64 個樣本——那是因為 ART 內部預設 batch_size=64。Optuna 把它固定在 1，是確保 predict 函數行為可預期的做法。
